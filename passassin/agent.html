Agent

Overview

To allow for functionality testing, Agent will start out with some of the functionality that will only be present in PlayerAgent.

Agent needs:

  • Hitbox arrangement - use mesh over capsule for collision channel
  • Animation State Modifier Tracking: crouching and aiming alter the other animations
  • Weapon object and shooting functionality
  • Trackable health
  • (Temporary for Player)
    • Input mapped Locomotion
    • Follow Camera on boom for third-person view

The current way the weapon shoots is it looks [range] distance down the camera direction, and draws a trace from the muzzle socket of the gun. I added a debug draw to show the trace, add a sphere at collision, and a color indicator for, no hit (red), hit (yellow), and agent hit (green).

With the mesh skeletons that come with the Unreal mannequins, they provide complex and "visually accurate" hitboxes, so with the capsule ignoring the collision channel the gun uses, the player only actually hits if they hit somewhere on the body.

AgentAnimInstance

ABP_Manny is the only blueprint that is using Unreal's node graphs for its logic. AgentAnimInstance, still maintains the records for the animation modifier states, like crouching and aiming, to use Blend Poses by Bool to set the correct animation based on the Agent's actions.

Below shows crouching, aiming, and jumping all being used in combination with each other, blended into main animation states (like locomotion).

AgentObserver

I want to add a function to allow for rewinding of time, for dramatic short resets after death to get you back to try again quickly—and possibly for manual use. This class tracks all actions Agents perform in chronological order. This allows for more flexible/frequent records in addition to engine auto save states.

Player

The PlayerAgent has the smaller diversion from its parent; the player is actually ripping some of the parent's functionality away (ironic really), but it doesn't need as much new behavior.

Player needs:

  • (Taken from Agent)
    • Input mapped Locomotion
    • Follow Camera on boom for third-person view
  • A better shooting solution to handle the third-person camera offset problem
