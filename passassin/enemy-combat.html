Expanding Enemy Combat

Nerfing Enemies

The enemies need a way to shoot at the player without insta-killing them every time the player is spotted, so they need some built-in inaccuracy. I am going with a very simple approach that allows for potentially different weapon behaviors: the FireError is built with a separate random horizontal and vertical component. They start as a random degree within the range of a negative and positive degree maximum, then are converted into linear values. These values are applied to a calculated 'up' and 'side' axis derived from the straight vector out of the muzzle to the chest of the player, extended by the FireRange.

Below is the code for the error logic:

// Avoid gimbal lock
const FVector Ref = FMath::Abs(AimDirN.Z) < 0.999f ? FVector::UpVector : FVector::ForwardVector;
// Horizontal and Vertical Component of Aim Direction
const FVector SideAxis = FVector::CrossProduct(AimDirN, Ref).GetSafeNormal();
// Derived UpVector to account for rotation
FVector UpAxis = FVector::CrossProduct(SideAxis, AimDirN);

// Unique random offset based on angle error projected onto both reference axes
float RandDegH = FMath::FRandRange(-FiringErrorDegMax, FiringErrorDegMax);
float HorizontalOffset = FireRange * FMath::Tan(FMath::DegreesToRadians(RandDegH));

float RandDegV = FMath::FRandRange(-FiringErrorDegMax, FiringErrorDegMax);
float VerticalOffset = FireRange * FMath::Tan(FMath::DegreesToRadians(RandDegV));

// Apply error shape to shoot target
const FVector FireError = (SideAxis * HorizontalOffset) + (UpAxis * VerticalOffset);
const FVector ToAimPoint = (AimDirN * FireRange) + FireError;
TraceEnd = TraceStart + ToAimPoint.GetSafeNormal() * FireRange;

Rather than using a radial error, I am separating these values to accommodate unique spread behaviors, such as a weapon having more vertical error than horizontal.

Additionally, there is a logic gate that avoids first-shot headshots; if the first round of an attack is a headshot, it is instead treated as a bodyshot for damage. Therefore, the player will never be instantly killed as soon as an enemy pulls the trigger. If I intend on the gameplay being more brutal, it can always be removed to up the sense of danger; otherwise this 'realistic' outcome would feel robotic and likely be experienced as unfair.
